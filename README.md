# CS-360-Mobile-Architect-Programming


## Project Three: Warehouse Inventory Tracker

For Project Three, I developed a mobile inventory tracking application using Android Studio and Java. The main goal of the application was to give users a simple way to manage inventory without having to keep track of everything manually. The application was designed to allow users to log in, view inventory, add new items, update quantities, and remove items when needed. Working in retail helped me understand how important accurate inventory information can be, especially when trying to keep products available for customers.

When designing the application, I wanted to keep everything simple and easy to navigate. The app needed a login screen and an inventory management screen where users could access the main features. I focused on making the buttons, text fields, and layout easy to understand so users would not have to spend unnecessary time figuring out how to complete a task. I also considered how the application would handle inventory information and user accounts. I believe the design was successful because it focused on the main purpose of the application without adding unnecessary features that could make it confusing.

My approach to coding the application was to work on one section at a time instead of trying to complete everything at once. I used Java to build the application's functionality and SQLite to store user and inventory information. I learned that breaking the project into smaller tasks made it easier to understand the code and identify problems. I also spent time reviewing errors and making changes when something did not work correctly. This is an approach I plan to continue using in future programming projects because it makes the development process more manageable.

Testing was another important part of developing my application. I used the Android Emulator to run the app and check how the different features worked. I focused on making sure users could navigate between screens and that the inventory functions worked as expected. Testing helped me identify problems that were not always obvious when looking at the code. I learned that an application can build successfully and still have issues when someone actually tries to use it. This showed me why testing throughout development is important instead of waiting until everything is finished.

One of the biggest challenges I faced was getting the different parts of the application to work together correctly. Connecting the user interface to the Java code and database required troubleshooting and making adjustments along the way. There were times when I had to go back through my code to figure out why something was not working. Instead of starting over, I learned to look at each part of the problem and make smaller changes until I could identify the issue. This helped me become more confident in my ability to troubleshoot problems.

I believe one of my biggest accomplishments in this project was working with the SQLite database to manage inventory information. Learning how to store, retrieve, and update data helped me better understand how mobile applications work beyond what users see on the screen. It also gave me experience connecting the database to the application's features. Overall, this project helped me improve my skills in Java, Android Studio, database management, and application design. I still have more to learn, but completing this project has given me a better understanding of the mobile development process and how I can apply these skills in future projects.
